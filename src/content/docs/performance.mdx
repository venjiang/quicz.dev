| --- | --- | --- |

| P99 | **62.1 μs** | |
| P99.9 | **85.3 μs** | |

5000 iterations, macOS loopback, ReleaseFast.

## Methodology

- **Protocol** — QUIC v1, 1-RTT installed keys (TLS handshake bypassed for a transport-only measurement).
- **Socket** — loopback UDP, 1200-byte datagrams.
- **Build** — `zig build-exe -OReleaseFast`.
- **Platform** — Apple M-series, macOS, Zig 0.16.
- **Workload** — 64 MB single-stream upload; threaded client/server; CUBIC; std.Io async; ~102K datagrams pipelined with ACK feedback.

## Run it

```sh
zig build run-quic-bench

# or build the ReleaseFast binary directly
zig build-exe -OReleaseFast --dep quicz \
  -Mroot=examples/quic_bench.zig -Mquicz=src/lib.zig \
  --name quicz-quic-bench -femit-bin=zig-out/bin/quicz-quic-bench
./zig-out/bin/quicz-quic-bench
```

## Reading these numbers

- **Not a controlled head-to-head.** quicz's figure is this repo's benchmark on
  macOS; the quic-go / quiche / s2n-quic figures are ≈ the TQUIC project's
  numbers on Linux; msquic's is secnetperf. Different harnesses, OSes, and
  kernel I/O paths — treat the column as indicative, source-attributed context.
- **No GSO / XDP for quicz here.** macOS lacks them; msquic's top number needs
  Linux XDP kernel bypass + `UDP_SEGMENT`.
- **Linux + GSO should lift quicz further** (sendmmsg + `UDP_SEGMENT`).
- **Loopback still pays the kernel UDP stack** — quicz's in-memory connection
  model does no kernel bypass, so loopback overhead applies.
- **Go / Rust benefit from zero-copy `sendmsg` and GSO on Linux**, which this
  macOS run does not exercise.
