## 回声延迟

| 百分位 | 延迟 | 说明 |
| --- | --- | --- |
| P50 | **20.2 μs** | 1 KB 完整 QUIC 往返（加密 + 发送 + 接收 + 解密 + 回显） |
| P99 | **62.1 μs** | |
| P99.9 | **85.3 μs** | |

5000 次迭代，macOS loopback，ReleaseFast。

## 测试方法

- **协议** —— QUIC v1，安装 1-RTT 密钥（绕过 TLS 握手，仅测传输层）。
- **套接字** —— loopback UDP，1200 字节 datagram。
- **构建** —— `zig build-exe -OReleaseFast`。
- **平台** —— Apple M 系列，macOS，Zig 0.16。
- **负载** —— 64 MB 单流上传；client/server 分线程；CUBIC；std.Io 异步；约 102K datagram 流水线 ACK 反馈。

## 运行

```sh
zig build run-quic-bench

# 或直接构建 ReleaseFast 二进制
zig build-exe -OReleaseFast --dep quicz \
  -Mroot=examples/quic_bench.zig -Mquicz=src/lib.zig \
  --name quicz-quic-bench -femit-bin=zig-out/bin/quicz-quic-bench
./zig-out/bin/quicz-quic-bench
```

## 如何读这些数字

- **非受控对比。** quicz 数字是本仓库在 macOS 上的基准；quic-go / quiche / s2n-quic 约等于
  TQUIC 项目在 Linux 上的数字；msquic 来自 secnetperf。harness、OS、内核 I/O 路径都不同——
  该列仅作带来源标注的指示性参考。
- **quicz 此处无 GSO / XDP。** macOS 不具备；msquic 的最高值需要 Linux XDP 内核旁路 +
  `UDP_SEGMENT`。
- **Linux + GSO 预期可进一步提升 quicz**（sendmmsg + `UDP_SEGMENT`）。
- **loopback 仍要付内核 UDP 栈开销** —— quicz 的内存连接模型不做内核旁路，loopback 开销适用。
- **Go / Rust 在 Linux 上受益于零拷贝 `sendmsg` 与 GSO**，本次 macOS 运行未涉及。
