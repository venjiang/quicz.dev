## 线上验证，不只是单元测试

quicz 的握手与 stream 路径由真实 UDP 探针覆盖：进程内 loopback、独立进程 Zig，以及
启用证书校验的 Go / Rust 对端。

```sh
$ examples/interop/run_external_interop.sh all
# 对 quic-go (Go)、quiche (Rust)、s2n-quic (Rust) 的证书校验互通：
# 握手 + 传输，stream 0/4 上带 FIN 的 echo —— 全程开启证书校验。
```

## quicz 目前已实现

<div className="qz-split">
<div>

- **纯 Zig TLS 1.3 + 0-RTT** —— 无 C 密码学；ECDSA P-256、X25519、X25519Kyber768（后量子）、AES-128/256-GCM、ChaCha20-Poly1305、会话恢复。
- **QUIC v1 & v2 transport** —— stream、flow control、连接迁移、path validation、Retry、stateless reset、密钥更新、版本协商、DATAGRAM、multipath、ECN、PMTUD、GSO/GRO、连接池、qlog。
- **Loss recovery + NewReno / CUBIC / BBR**，含报文 pacing。
- **HTTP/3** —— 完整连接管理、SETTINGS、GOAWAY、stream 状态机、QPACK 静态 + 动态表。
- **WebTransport**（完整会话管理）**+ HTTP Datagrams** (RFC 9297) **+ 流重置部分交付**。
- **线路级互通验证**：quic-go、quiche、s2n-quic。

## 互操作矩阵

| 对端 | 语言 / 协议栈 | 探针 |
| --- | --- | --- |
| quic-go | Go | 启用证书校验的 echo client/server + `run_external_interop.sh` |
| quiche | Rust | 启用证书校验的握手 + 传输 |
| s2n-quic | Rust | 启用证书校验的握手 + 传输 |
| QUIC-Interop-Runner | — | handshake、transfer、retry 自测 |

自己跑一遍：[示例指南](/zh-cn/examples/)。

## quicz 横向对比

权威功能矩阵在四个协议栈上追踪 37 项能力，覆盖率汇总如下：

| 指标 | quic-go | quiche | s2n-quic | quicz |
| --- | --- | --- | --- | --- |
| 传输层（19 项） | 19/19 | 14/19 | 14/19 | 19/19 |
| 拥塞控制（4 项） | 4/4 | 4/4 | 3/4 | 4/4 |
| 密码套件（5 项） | 5/5 | 5/5 | 5/5 | 5/5 |
| 应用层（6 项） | 6/6 | 3/6 | 0/6 | 6/6 |
| 平台（3 项） | 2/3 | 0/3 | 1/3 | 1/3 |
| **合计（37 项）** | **36/37** | **26/37** | **23/37** | **36/37** |

quicz 在传输层、拥塞控制、密码套件**以及**应用层（完整 HTTP/3、QPACK、WebTransport、
HTTP Datagrams）上已与 quic-go 持平，剩余差距仅为平台特性。完整 37 行逐项对比见
[功能对比](/zh-cn/comparisons/)。

## 不在范围内

以下两项是某个其它协议栈独有的平台特性，不在 quicz 路线图中：

- **FIPS 140-3** —— 仅 quic-go（Go 1.26+）。
- **XDP 零拷贝 I/O** —— 仅 s2n-quic。

权威状态与验收证据见[传输任务矩阵](https://github.com/venjiang/quicz/blob/main/docs/zh-CN/quic_transport_tasks.md)。
API 趋于稳定但仍在演进。
